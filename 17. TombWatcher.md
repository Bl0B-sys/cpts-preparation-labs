В выводе нас больше всего интересует свойство `LastKnownParent:OU=ADCS,DC=tombwatcher,DC=htb`. 

**LastKnownParent** — это системный атрибут в Active Directory, который указывает на **последний контейнер (родительский объект)**, в котором находился объект перед своим удалением.

При восстановлении объекта из корзины Active Directory:

1. Active Directory считывает метаданные объекта (включая lastKnownParent).
2. Он пытается воссоздать объект в исходном контейнере (подразделении).
3. Объект фактически повторно вставляется в это подразделение вместе со своими атрибутами.

Так как у нашего пользователя `john` есть `GenericAll` над объектом учета `ADCS@TOMBWATCHER.HTB`, мы можем восстановить учётку `cert_admin`. 

```

> [!NOTE] Условия эксплуатации ESC15
> 1. Используется **шаблон сертификата версии 1 (Schema Version 1)**. Шаблоны версии 2+ (в том числе дубликаты) неуязвимы.
> 2. В шаблоне включен **Subject Name = Supplied in the request**, что позволяет заявителю самостоятельно указывать Subject/SubjectAltName.
> 
> ```
> Enrollee Supplies Subject           : True
> ```
> 
> 3. **Не требуется одобрение администратора CA** и **подпись Enrollment Agent** — сертификат выдается автоматически.
> 4. **CA не переводит запрос в режим ожидания (pending)**, поэтому сертификат выдается сразу.
> 5. У злоумышленника есть право **Enroll** (выпуск сертификата) на этот шаблон (например, через группы **Domain Users** или **Authenticated Users**). Если Enroll доступен только администраторам PKI, эксплуатация невозможна без дополнительных привилегий.
> ```
>Permissions
>	Enrollment Permissions
>		Enrollment Rights         TOMBWATCHER.HTB\cert_admin
> ```
> 6. **Дополнительно**. Из-за бага в обработке **Application Policies** у шаблонов **версии 1** злоумышленник может не только указать имя другого пользователя, но и **самостоятельно добавить в запрос Application Policies**(например, Client Authentication), которых в шаблоне изначально не было. CA ошибочно доверяет этим политикам и включает их в выданный сертификат.

### Что происходит на самом деле

1. **У `cert_admin` есть право Enroll на шаблон WebServer.**
2. Этот шаблон **уязвим к ESC15**, поэтому можно добавить произвольный Application Policy.

В первом запросе ты **не добавляешь возможность получения сертификата на авторизацию**, а добавляешь совсем другой EKU:

```
1.3.6.1.4.1.311.20.2.1
Certificate Request Agent
```

То есть ты говоришь CA:

> "Выдай мне сертификат агента регистрации."

И из-за ESC15 CA отвечает:

> "Хорошо."

Хотя шаблон WebServer вообще не должен выдавать такие сертификаты.

Получается:

```
cert_admin
      │
      ▼
WebServer + ESC15
      │
      ▼
cert_admin.pfx
(EKU = Certificate Request Agent)
```
