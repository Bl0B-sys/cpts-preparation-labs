---
Разберём цепочку по шагам.

### 1. Изначально мы были `sbrown`

После получения SSH-доступа:

```
ssh sbrown@snoopy.htb
```

мы находились под непривилегированным пользователем `sbrown`.

При проверке `sudo` выяснилось, что `sbrown` может запускать **конкретную команду от root**:

```
sudo clamscan ...
```

То есть имеем примерно такую ситуацию:

```
sbrown
  │
  └── sudo clamscan <файл>
              │
              └── выполняется как root
```

Сам по себе `clamscan` не является shell и не даёт нам произвольно выполнять команды от root. Поэтому нужно было найти способ заставить **сам ClamAV**, работающий с root-привилегиями, раскрыть какие-нибудь root-секреты.

---

### 2. Нашли уязвимость CVE-2023-20052

В используемой версии ClamAV существовала уязвимость в обработчике **DMG-файлов**.

Суть уязвимости — **XXE (XML External Entity)**.

Упрощённо:

```
DMG-файл
   │
   ▼
ClamAV парсит его содержимое
   │
   ▼
XML parser обрабатывает внешний entity
   │
   ▼
может прочитать локальный файл
```

И вот здесь появляется самое важное:

**ClamAV запускается через `sudo`, поэтому парсер работает с правами root.**

Следовательно, если заставить его прочитать файл, доступный только root, мы получим содержимое этого файла.

---

### 3. Почему именно SSH private key

В качестве интересующего файла выбрали приватный SSH-ключ root:

```
/root/.ssh/id_rsa
```

Идея payload была примерно такой:

```
XXE
 │
 └── "прочитай /root/.ssh/id_rsa"
```

То есть мы не заставляем root выполнять нашу команду.

Мы заставляем **root-процесс ClamAV прочитать файл root**.

Это важное различие.

---

### 4. Почему нельзя было просто подсунуть обычный DMG

Сначала создали обычный DMG:

```
genisoimage ... -o progname.dmg /mnt
```

Но ClamAV не воспринимал его так, как требовалось для эксплуатации.

Поэтому использовали `libdmg-hfsplus` и изменили его код генерации DMG.

В частности, в `resources.c` изменили XML-данные, которые библиотека записывает внутрь DMG.

В результате получился DMG примерно такой структуры:

```
DMG
 └── XML plist
      └── XXE entity
           └── /root/.ssh/id_rsa
```

То есть мы подготовили **специально сформированный DMG**, который при разборе ClamAV заставляет XML-парсер обратиться к локальному файлу.

---

### 5. Почему используется `--debug`

На машине:

```
sudo clamscan --debug /home/sbrown/scanfiles/c.dmg
```

ClamAV начинает разбирать специально подготовленный DMG.

Из-за XXE он обращается к:

```
/root/.ssh/id_rsa
```

и содержимое этого файла оказывается в выводе/debug-информации ClamAV.

Получается:

```
sbrown
  │
  │ sudo clamscan
  ▼
ClamAV (root)
  │
  │ парсит наш DMG
  ▼
XXE
  │
  │ читает файл
  ▼
/root/.ssh/id_rsa
  │
  ▼
вывод ClamAV
  │
  ▼
мы получаем приватный ключ
```

---

### 6. А вот здесь происходит фактическое повышение привилегий

Мы сохраняем полученный приватный ключ:

```
root_rsa
```

выставляем правильные права:

```
chmod 600 root_rsa
```

и используем его:

```
ssh -i root_rsa root@snoopy.htb
```

Теперь SSH-сервер проверяет соответствие приватного ключа публичному ключу root и впускает нас как:

```
root
```

То есть итоговая цепочка:

```
sbrown
  │
  │ sudo clamscan
  ▼
ClamAV с UID 0
  │
  │ CVE-2023-20052
  ▼
XXE
  │
  │ чтение root-файла
  ▼
/root/.ssh/id_rsa
  │
  │ получаем ключ
  ▼
SSH authentication
  │
  ▼
root
```

### Главное, что стоит запомнить

Это **не классическая `sudo`-эскалация**, где мы превращаем разрешённую программу в shell.

Здесь используется комбинация:

**`sudo` → привилегированный ClamAV → уязвимый DMG parser → XXE → чтение `/root/.ssh/id_rsa` → SSH как root.**

Именно поэтому право запускать `clamscan` через `sudo` оказалось критичным: **уязвимость сама по себе была бы намного менее полезна, если бы ClamAV работал от имени обычного пользователя.**
