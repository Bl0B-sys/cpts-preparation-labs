> [!NOTE] As-rep-roasting
> **AS-REP Roasting** — это атака на протокол Kerberos, позволяющая получить материал для офлайн-подбора пароля пользователя **без предварительной аутентификации**. Атака возможна только для учетных записей, у которых в Active Directory отключена опция **Kerberos Pre-Authentication**.
> 
> При обычной аутентификации Kerberos клиент сначала отправляет контроллеру домена (KDC) запрос **AS-REQ**, содержащий метку времени, зашифрованную ключом, сформированным из пароля пользователя. KDC расшифровывает эту метку времени, тем самым убеждается, что клиент знает правильный пароль, после чего отправляет ответ **AS-REP**, содержащий билет TGT и данные, необходимые для дальнейшей аутентификации.
> 
> Если же предварительная аутентификация отключена, KDC не требует подтверждения знания пароля и сразу отвечает на запрос **AS-REP**. Часть этого ответа зашифрована ключом пользователя (производным от его пароля). Любой пользователь домена может запросить такой ответ для соответствующей учетной записи, сохранить его и выполнять **офлайн-подбор пароля** с помощью специализированных инструментов. При этом перебор происходит локально и не создает большого количества запросов к контроллеру домена.
> ![Pasted image 20260715150113](./screenshots/Pasted%20image%2020260715150113.png)
> Эффективность AS-REP Roasting напрямую зависит от сложности пароля: слабые пароли могут быть успешно подобраны за короткое время, тогда как длинные и случайные пароли практически не поддаются такой атаке.
> 
> В современных версиях Active Directory предварительная аутентификация Kerberos включена по умолчанию, поэтому данная атака возможна только в случае, если администратор вручную отключил эту защиту (например, для обеспечения совместимости со старыми приложениями или устаревшими учетными записями).
> 
> |AS-REP Roasting|Kerberoasting|
> |---|---|
> |Не требуется аутентификация|Требуется любая доменная учетная запись|
> |Используется AS-REP|Используется TGS-REP|\
> |Атакуются пользователи с отключенной Pre-Authentication|Атакуются сервисные учетные записи с SPN|
> |Получается материал для подбора пароля обычного пользователя|Получается материал для подбора пароля сервисной учетной записи|

> BloodHound одна из первых утилит, которая должна запускаться при получении учетных данных. 
>

Для своей работы он использует обычные механизмы взаимодействия с Active Directory, такие как LDAP, SMB, RPC и другие штатные протоколы, предназначенные для чтения информации о домене. Возможность удаленного подключения к хостам влияет лишь на выполнение последующих атак, но не на процесс сбора данных и анализа BloodHound.
