>**Follina** — это уязвимость в компоненте **Microsoft Support Diagnostic Tool (MSDT)**, позволявшая выполнить произвольный код при открытии документа Microsoft Office без использования макросов.
>
>Принцип работы заключается в том, что документ Office содержит внешнюю ссылку на удалённый HTML-файл. При открытии документа Office автоматически загружает этот HTML, который перенаправляет выполнение на специальный URI `ms-msdt:`. Этот URI запускает утилиту MSDT с параметрами, сформированными злоумышленником. Из-за недостаточной проверки входных данных MSDT выполняет встроенную команду PowerShell или другую полезную нагрузку с правами текущего пользователя.
> 
>Главная особенность Follina заключается в том, что атака **не требует включения макросов**. В некоторых сценариях было достаточно даже предварительного просмотра документа в Проводнике, поскольку Office начинал обрабатывать внешние ссылки ещё до полного открытия файла.

> [!NOTE] **WSUS Privilege Escalation / Lateral Movement (SharpWSUS)**
> ##### Идея атаки.
> **WSUS (Windows Server Update Services)** — это сервер централизованного распространения обновлений Windows. Все управляемые компьютеры регулярно обращаются к нему, доверяют публикуемым обновлениям и устанавливают их. Если злоумышленник получает контроль над сервером WSUS, он может использовать этот механизм доверия для доставки собственного кода на любые машины, управляемые данным сервером.
> 
> ##### Почему это опасно.
> WSUS часто обслуживает критически важные системы (Domain Controller, файловые серверы, серверы резервного копирования и т.д.) и имеет возможность взаимодействовать с ними даже при наличии сетевой сегментации. Благодаря этому компрометация одного WSUS-сервера может стать каналом для дальнейшего продвижения по инфраструктуре.
> 
> ##### Общая схема атаки
> 1.  Компрометируется сервер WSUS.
> 2. Выполняется перечисление управляемых компьютеров и выбирается цель.
> 3. Создается вредоносное обновление, которое вместо обычного патча запускает подписанный Microsoft бинарный файл с нужной полезной нагрузкой.
> 4. Для целевого компьютера создается отдельная группа WSUS (чтобы обновление не получили другие машины).
> 5. Вредоносное обновление одобряется (approve) для этой группы.
> 6. Когда целевой компьютер в следующий раз проверит наличие обновлений, он скачает и выполнит опубликованный пакет с правами SYSTEM.
> 7. После успешного выполнения обновление и временная группа удаляются для сокрытия следов.
> 
> #### Особенности атаки
> - Атака не эксплуатирует уязвимость WSUS — она злоупотребляет его штатным механизмом доставки обновлений.
> - Выполнение происходит только тогда, когда клиент самостоятельно обращается к WSUS за обновлениями, поэтому время срабатывания заранее неизвестно.
> - Для запуска используются подписанные Microsoft исполняемые файлы, что позволяет встроиться в нормальный процесс установки обновлений.
>
> Подробнее про эксплуатацию в [статье](https://www.lrqa.com/en/cyber-labs/introducing-sharpwsus/)
